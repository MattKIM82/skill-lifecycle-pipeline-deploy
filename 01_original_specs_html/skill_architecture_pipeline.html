03 / L5–L8 계층별 구현 상세

L5 · Knowledge Construction

입력
계약 + 사용자 요구 + 승인된 업무 사례
구현 방법
AI가 지식 후보를 추출하고 용어·조건·우선순위를 정규화. 사람이 업무 정책과 성공 조건을 확정. 코드가 rule_id, 출처, 버전 및 참조 무결성을 검사.
산출물
knowledge.json, policy.json, intent_catalog.json
통과 기준
모든 필수 규칙에 근거와 소유자 존재; 미확인 규칙은 unknown으로 표시.

L6 · Workflow Construction

입력
L5 지식 + capability registry + 입출력 타입
구현 방법
AI가 DAG 후보와 분기를 생성. 코드가 타입 호환, 순환, 선행 조건, 부작용, 오류 처리 및 중단 정책을 검사. 사용자 요구를 기존 툴 순서와 구분.
산출물
workflow.json, dependency_graph.json, adapter bindings
통과 기준
모든 경로의 필수 입력 공급 가능; 불허 경로 및 무한 루프 차단.

L7 · Skill Construction

입력
승인된 규칙·워크플로·기능 ID
구현 방법
AI가 사용자 의도, 질문 조건, 도구 선택 지침을 작성. 컴파일러가 공통 규칙을 참조로 삽입하고 스키마 및 중복 검사. 생성된 스킬은 빌드 산출물로 취급.
산출물
SKILL.md, skill manifest, intent routing map
통과 기준
모든 참조 유효; 규칙 충돌 없음; 소스·모델·프롬프트 버전 기록.

L8 · Agent Validation

입력
스킬 후보 + 계약 테스트 + 업무 테스트 + 실제 실행 환경
구현 방법
케이스 생성, 격리 실행, 결정론적 평가와 독립 AI 평가, 실패 큐레이션, 수정, 재시험. 독립 평가 데이터와 배포 게이트 유지.
산출물
eval_report.json, evidence/, failure_cases.jsonl, release manifest
통과 기준
필수 테스트 전부 통과; 미검증 필수 기능 없음; 승인 및 롤백 준비.

04 / L1–L4 표준 계약: 입력이 부족하면 생성하지 않는다

입력필수 확인
L1tool_id, version, capability_id, 실행 진입점, 인증/라이선스, 부작용 및 권한
L2JSON Schema, 기본값, 단위, 허용 범위, 교차 제약, 의존성, 권장 사용 조건
L3job_id, 상태 모델, timeout, 동시성, 중단·재시작 가능 여부, 오류 코드, 재시도 안전성

계약 테스트가 실패하면 업체 또는 코드 소유자에게 근거와 함께 반환. 지원하지 않는 실행 기능은 명시적으로 unavailable 처리하고 스킬이 약속하지 않도록 한다.

  "capability_id": "analyze",

    "properties":{"n":{"type":"integer","minimum":1,"maximum":100}}},
  "output_schema_ref":"schemas/result.json",
  "adapter_id":"local_cli", "timeout_s":60,
  "supports_cancel":false, "idempotent":false,
  "oracle_ref":"oracles/analyze_v1.json",
  "source_ref":"approved_contract_v1", "status":"verified"

05 / 테스트 생성 및 Eval 설계

테스트 종류생성 근거 / 판정
정상·경계·오류L2 스키마에서 min/max, 범위 밖, 누락, 잘못된 타입을 코드로 생성. 승인된 오류 계약으로 판정.
상태 및 제어L3 지원 기능에 대해 timeout, 중단, 동시 실행, 재시도 및 상태 전이 검사.
결과 검증L4 골든 데이터와 허용오차 비교. 정답이 없는 경우 승인된 불변조건 또는 관계 기반 테스트 활용; 근거 없는 정답 생성 금지.
업무 의도L5 사용자 요구에서 모호한 명령, 추가 질문, 금지 행위, 복합 시나리오 생성. 독립 평가 기준으로 판정.
워크플로·스킬L6–L7에서 잘못된 순서, 누락, 충돌, 불필요한 호출 및 완료 허위 보고 탐지.

테스트 생성 AI와 평가 AI의 컨텍스트를 분리하고, 가능하면 모델도 분리한다. 실제 실행 결과와 결정론적 판정이 우선하며 AI 판단만으로 필수 게이트를 통과시키지 않는다. 생성/수정 데이터와 잠금된 holdout을 분리한다.

test_case.json (예시)
{"case_id":"boundary_001", "requirement_id":"R-01",
 "input":{"n":0}, "expected":{"status":"invalid_input"},
 "oracle":"approved_contract", "severity":"critical",
 "split":"regression", "seed":42}

07 / 구현 구조 및 상태 관리

skill_factory/
  contracts/          # L1–L4, schemas, adapters, oracles
  knowledge/          # L5: rules, policies, intents
  workflows/          # L6: DAG definitions
  skills/             # L7: source and compiled packages
  tests/              # L8: generated / regression / locked holdout
  engine/
    admission.py      # contract gate
    synthesize.py     # AI provider adapter + structured generation
    compile.py        # deterministic checks
    execute.py        # sandbox / runtime adapter
    evaluate.py       # oracle + independent judge
    curate.py         # reproducible failure corpus
    refine.py         # scoped patch proposals
    release.py        # approval, atomic publish, rollback
    state.py          # SQLite transactions / checkpoints
  prompts/            # versioned templates
  runs/               # evidence, immutable snapshots
  releases/           # versioned packages
상태 머신

NEW → ADMITTED → GENERATED → TESTED → EVALUATED → RELEASE_CANDIDATE → APPROVED → PUBLISHED. 실패 시 TRIAGED → PATCH_PROPOSED → RETEST 또는 BLOCKED. 중단은 CANCELLED / PAUSED로 기록하고 지원 가능한 단계만 재개한다.

각 실행은 run_id, 입력 해시, stage, attempt, artifact_refs, model_id, prompt_version, budget, parent_run_id를 저장한다. SQLite 트랜잭션과 파일 해시로 상태 및 증거를 연결한다. 부작용 있는 호출은 멱등성 확인 없이 재시도하지 않는다.

# orchestration.py — 설계용 의사코드, 실제 adapter 구현 필요
 def build(contract, user_requirements, max_attempts=3):
     admitted = admission.verify(contract)
     if not admitted.ok:
         return state.block(admitted.evidence)
     candidate = synthesize.generate(admitted, user_requirements)
     for attempt in range(max_attempts):
         compile.validate(candidate)
         suite = tests.build(candidate, admitted)
         evidence = execute.run_isolated(suite, candidate)
         result = evaluate.check(evidence, approved_oracles)
         state.checkpoint(candidate, result)
         if result.required_pass:
             regression = evaluate.locked_regression(candidate)
             if regression.pass_gate:
                 return release.request_approval(candidate, regression)
             result = regression
         failures = curate.collect(result)
         if failures.requires_owner or failures.repeated:
             return state.block(failures)
         candidate = refine.propose(candidate, failures)
     return state.block("iteration_limit")
AI 호출 계약

입력은 승인된 문서·규칙 ID·실패 증거·허용 수정 범위, 출력은 JSON Schema로 제한한다. 생성 프롬프트: “근거가 있는 기능만 사용하고, 불명확한 조건은 unknown으로 표시하며, 모든 규칙에 source_ref를 제공하라.” 평가 프롬프트: “후보 생성자의 설명을 신뢰하지 말고 실행 증거와 승인 기준을 대조해 verdict, evidence_ref, uncertainty를 반환하라.” 수정 프롬프트: “실패를 재현한 규칙에 한해 최소 diff를 제안하고 평가 기준은 변경하지 말라.”

모델 교체는 provider adapter로 격리. 사내 승인 모델/서버, 프로젝트 경로 제한, venv, 외부 전송 차단을 기본 전제로 한다. 비밀값은 로그에서 제거하고 실제 툴의 위험한 실행은 격리 또는 승인한다.

08 / 유지보수 및 드리프트 제어

Single Source of Truth: rule_id와 capability_id를 중심으로 원천 명세를 버전 관리하고 스킬은 이를 참조해 생성한다. 자연어 중복은 컴파일 산출물로만 허용하며 원천 수정 후 재생성한다.

변경 감지: 계약·툴·업무 규칙·프롬프트·모델 변경 시 해시 및 구조적 diff → 역참조 그래프로 영향 스킬 식별 → 의미적 충돌 검사 → 관련 및 전체 회귀 → 승인. 모델/툴 버전과 평가 환경을 함께 고정한다.

배포: 승인된 패키지에 manifest와 증거 해시를 기록하고 이전 버전을 보존한다. 호환되지 않는 툴 버전에서는 이전 스킬도 재검증 후 롤백한다. 평가 데이터는 별도 권한으로 보호한다.

09 / 단계별 구현 계획

단계완료 조건
P0 · 계약 표준화두 소스 유형 모두 동일 스키마로 입수, 부족 항목 차단
P1 · L5–L7 MVP대표 기능 1개로 지식→DAG→스킬 생성 및 정적 검사 재현
P2 · L8 Eval실제 호출 증거, 독립 오라클, 정상·경계·오류 테스트 자동 판정
P3 · 개선 루프의도적으로 삽입한 결함 수집·재현·수정·회귀 및 종료 조건 검증
P4 · 유지보수명세 변경 시 영향 스킬만 우선 재생성, 전체 회귀 및 승인·롤백 검증
P5 · 확장두 번째 툴을 추가하여 adapter/contract 외 엔진 재사용성 입증

보고 결론: 스킬을 채팅으로 일회성 작성하는 방식에서, 표준 계약을 입력받아 스킬의 전체 생애주기를 코드로 관리하는 개발 체계로 전환한다. Artifact 01·02는 정보 확보와 책임 모델, Artifact 03은 공통 L5–L8의 실제 자동화 설계다.

구현 경계 (Python 의사코드)

class ToolAdapter(Protocol):
    def execute(self, capability_id, validated_input, run_context): ...
    def status(self, handle): ...
    def cancel(self, handle): ...

# engine은 A/B 분기 대신 등록된 계약과 어댑터를 사용
contract = admission.verify(load_manifest(tool_id))
adapter = registry.resolve(contract.adapter_id)  # 승인된 구현만
suite = testgen.build(contract, approved_business_rules)
for case in suite:
    validate(case.input, case.capability.input_schema)
    evidence = adapter.execute(case.capability.id, case.input, context)
    verdict = oracle_registry.evaluate(case.oracle_ids, evidence, case)
    store.record(case, evidence, verdict)

미지원 상태 조회나 취소는 명시적으로 unsupported 처리한다. 어댑터가 있다고 가정해 성공 판정하지 않는다. A 출력과 B 입력의 연결은 구조뿐 아니라 단위·의미·전제조건까지 검증하며, 변환은 별도 버전 관리 및 테스트를 거친다.

신규 툴 온보딩 완료 기준

① 계약 스키마 통과 ② 실제 호출 및 오류 계약 테스트 통과 ③ 독립 기대 결과 확보 ④ 툴별 어댑터·검증기 등록 ⑤ 공통 엔진 소스 변경 없이 스킬 생성·Eval·회귀 수행. 미충족 항목은 차단하고 담당자에게 이관한다. 공통 엔진 자체의 기능 부족이 확인되면 별도 설계 변경으로 관리한다.
