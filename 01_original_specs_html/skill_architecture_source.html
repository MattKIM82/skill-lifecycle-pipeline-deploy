03 / 공통 변경·드리프트 관리

Single Source of Truth: 공통 규칙은 ID를 부여하여 한 곳에서 관리하고 스킬은 이를 참조한다. 생성된 스킬은 원본 계약 버전과 연결한다.

변경 감지 → 계약 diff → 영향받는 워크플로·스킬 식별 → 재생성 → 계약 및 회귀 테스트 → 승인·배포. 실패 시 이전 검증 버전 유지.

지표: 계약 테스트 통과율, 필수 기능 커버리지, 규칙 충돌 건수, 사용자 의도 충족률, 허위 완료율. 변경 건별 불일치 발생률은 변경 이력을 쌓아 추정하며 표본 수와 불확실성을 함께 보고한다.

04 / OPC 적용 예시 (가상)

사용자 요청: 입력 레이아웃과 공정 조건에 맞춰 OPC 실행 및 결과 검증.

입력 파일·단위·공정 조건 검사 → 작업 계획 및 승인 → OPC 실행 → 작업 상태 조회 → 산출물 검사 → 검증 툴 실행 → 업무 기준 충족 여부 판정.

파일 형식 또는 단위 불일치 시 실행 차단. 중단 후 재개가 지원되지 않으면 새 작업으로 재실행. 결과 파일이 있어도 검증 기준을 충족하지 않으면 완료로 표시하지 않는다.

05 / 자동 추출 실행 계획

① 저장소 및 빌드 환경 확인 → ② AST·호출 그래프 및 진입점 분석 → ③ 기존 테스트·매뉴얼 대조 → ④ 기능 계약 생성 및 근거 위치 연결 → ⑤ 실행 테스트 → ⑥ 전문가 검토 → ⑦ 스킬 생성·회귀 검증.

정적 분석만으로 확정할 수 없는 동적 동작은 미확인으로 표시하고 실행 근거를 확보한다. 사내 보안 범위 내에서 수행한다.
